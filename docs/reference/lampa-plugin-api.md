# Lampa: API для плагинов

Справочная страница. Источник — реальные (не минифицированные) исходники Lampa, склонированные локально
в `vendor/lampa-source/` (см. `.gitignore` — эта папка никогда не коммитится, это чисто справочная копия

разглядеть было нельзя. Все факты ниже — с указанием файла и строки в `vendor/lampa-source`, чтобы можно
было перепроверить самостоятельно.

Если факт из `CLAUDE.md` расходится с этой страницей — верить этой странице и поправить `CLAUDE.md`
(так и произошло с уточнением про `Lampa.TMDB` ниже).

## Component/Activity: два разных слоя

То, что обычно называют «Lampa-компонентом», на самом деле два слоя, и их легко перепутать.

**Реестр конструкторов** — `core/component.js`. `Lampa.Component.add(name, ctor)` просто кладёт
конструктор в объект по имени. `Lampa.Component.create(object)` делает `new ctor(object)` в try/catch —
**любое исключение в конструкторе тихо подменяется на встроенный `nocomponent`** («Здесь пусто»), без
видимой ошибки на экране. Это уже было в `CLAUDE.md`, подтверждено полностью.

**Рантайм-обёртка `ActivitySlide`** — `interaction/activity/slide.js`. Именно она вызывает методы
жизненного цикла компонента, и именно её поведение определяет, что обязательно, а что нет:

| Метод компонента | Вызывается | Обязателен? |
|---|---|---|
| `create()` | `ActivitySlide.create()` | Да — отсутствиеroняет конструктор в try/catch → `nocomponent` |
| `render(js)` | сразу после `create()`, для монтирования в DOM | Да, по той же причине |
| `start()` | `ActivitySlide.start()`, **после** переустановки плейсхолдер-контроллера `'content'` | Нет, но без него экран не подключится к навигации |
| `pause()` | опционально (проверка на существование перед вызовом) | Нет |
| `stop()` | опционально | Нет |
| `resize()` | опционально, на resize окна | Нет |
| `destroy()` | всегда, try/catch | Нет технически, но без него — утечки |
| `back()` | по запросу `Activity.backward()` | Нет |

Важная деталь, которую стоит знать при отладке асинхронных колбэков: `ActivitySlide.destroy()` после
вызова `component.destroy()` **заменяет все оставшиеся методы компонента на no-op** и ставит
`component.destroyed = true`. Если у плагина в полёте остался `fetch().then(() => this.someMethod())`
после закрытия экрана — он не упадёт, а просто молча ничего не сделает. Не нужно защищаться от этого
вручную доп. флагами, framework уже это делает.

`ActivitySlide.start()` **безусловно переустанавливает** плейсхолдер-контроллер `'content'` при каждом
входе на экран (в т.ч. при возврате с под-экрана) — это уже задокументировано подробно в
[`system-design/lampa-navigation-contract.md`](../system-design/lampa-navigation-contract.md) как причина,
по которой собственный `'content'`-контроллер плагина нужно регистрировать заново в `start()`, не только в
конструкторе. Подтверждено первоисточником один в один.

### Альтернативная, декларативная система (для справки, не для копирования)

Помимо ручного стиля (`this.start = function(){...}`, как у `torrents.js` и у нашего
`TorrentModPlugin`), в исходниках есть вторая, более декларативная система — `interaction/constructor.js`
(`Constructor(Map)`) с миксинами по битовой маске (`onCreate`/`onInit`/`onDestroy` и т.д., см.
`core/module/callback.js`). На ней построены нативные `interaction/season/season.js` и
`components/episodes.js` — последний одной строкой подключает Explorer-обвязку через
`CategoryModule.toggle(CategoryModule.MASK.base, 'Explorer')`, не создавая `new Explorer(...)` руками.
Наш плагин этим не пользуется и переписывать под это ничего не нужно — но если когда-то понадобится
объяснить, почему нативный экран серий «внутри» устроен иначе, чем наш — вот причина.

## Template: `Lampa.Template`

`interaction/template.js`. Два независимых способа подстановки, с разным поведением:

- **`Template.get(name, vars, like_static)`** — берёт сырую строку шаблона, прогоняет через
  `Lang.translate()` (отдельный механизм — `#{lang_key}` резолвится в текущий язык интерфейса,
  `core/lang.js`), затем делает плоскую замену `{var}` → строка, затем разворачивает `{@partial_name}`
  (буквальная подстановка сырой строки другого зарегистрированного шаблона). Возвращает jQuery-объект,
  если не запрошен `like_static`.
- **`Template.js(name, vars)`** — новее и быстрее: клонирует закэшированное DOM-дерево вместо
  повторного парсинга строки на каждый вызов. Поддерживает и `{var}`, и `{{nested.path}}` (путь через
  точку), и — важное отличие от `get()` — **если подставляемое значение само является DOM-узлом, оно
  вставляется как узел, а не строкой**.
- **`Template.add(name, html)`** — регистрирует/перезаписывает шаблон и сбрасывает кэш `js()`.
- **`Template.prefix(root, prefix)`** — сканирует потомков `root` на классы вида `prefix__suffix` и
  возвращает `{suffix: element}` — маленький BEM-хелпер вместо ручных `find('.explorer__xxx')`.
- **`Template.elem(tag, options)`** — императивный DOM-билдер (class/attrs/text/html/children) как
  альтернатива строковым шаблонам.

Категории шаблонов (`templates/`, ~150 файлов) — не исчерпывающе, но по назначению: `explorer/*` (левая
карточка + шапка/тело правого списка — см. ниже), `full/*` (экран карточки фильма/сериала), `season/*`
(строка серии, инфо, рейтинг), `torrent/*` (строка раздачи, файл, серийность, экраны ошибок подключения к
торрент-клиенту), `items/line.js` (обобщённая горизонтальная карточка), `selectbox/*` (`Select`-оверлей и
его строки), `settings/*` (секции экрана настроек), `search/*` (оверлей поиска), `player/*`, `card*.js`
(варианты постер-карточки), `feed/*` (лента).

Точное подтверждение разметки, которой мы пользуемся: `templates/explorer/main.js` — буквально то дерево
`.explorer__left > .explorer__card`, `.explorer__files > .explorer__files-head` + `.explorer__files-body`,
что уже задокументировано в `CLAUDE.md` по живым замерам. Совпадает дословно.

## Explorer, Scroll, Filter, Select, Controller, Layer

### Explorer (`interaction/explorer.js`)

Публичная поверхность: `movie()` (перерисовать левую карточку из `object.movie`), `appendFiles(el)` /
`appendLeft(el)` / `appendHead(el)` / `clearFiles()` / `clearLeft()` / `clearHead()`, `render(js)`,
`toggle()`, `destroy()`.

`toggle()` регистрирует контроллер `'explorer'`. То, что уже задокументировано в `CLAUDE.md` (`right` →
`Controller.toggle('content')`, `back` → `Activity.backward()`) — подтверждено. Плюс то, чего в
`CLAUDE.md` не было: `left` → `Controller.toggle('menu')`, а `up`/`down` **сначала** двигают позицию
скролла самой левой карточки (у неё свой внутренний `Scroll`), и только на границе передают управление
дальше в `Controller.toggle('head')` — то есть левая карточка сама по себе скроллится, и это тоже
управляется фреймворком, не только правый список.

Explorer также подмешивает небольшой `Emit`-миксин: `explorer.on('init'|'movie'|'controller'|'destroy',
cb)`. Это не используется ни в одном из наших мест, но может пригодиться, если понадобится реагировать на
пересборку контроллера Explorer, а не только читать его после факта.

### Scroll (`interaction/scroll.js`)

`minus(el)` подтверждён дословно: только помечает элемент классом `layer--wheight` и запоминает ссылку —
реальная арифметика в `Layer` (ниже). Полная поверхность:
`addSwipeDown`, `wheel`, `update`, `immediate`, `shift`, `vieport`, `isEnd`, `isFilled`, `append`,
`minus`, `height` (вариант, считающий от полного `window.innerHeight`, не от высоты шапки — в `CLAUDE.md`
не упоминался), `body`, `render`, `clear`, `params`, `position`, `restorePosition`, `nopadding`, `reset`,
`animated`, `destroy`. Плюс необязательные оверрайдимые колбэки `onWheel`/`onScroll`/`onEnd`/`onAnimateEnd`.

### Layer (`core/layer.js`) — то, что реально считает высоту

`frameUpdate` — обход всех `.layer--wheight`-элементов: `window.innerHeight − высота шапки − высота
навбара`, минус (если задан) `el.mheight.getBoundingClientRect().height`. `Layer.update(where?)` — публичная
функция, безопасна без аргумента.

**Важное уточнение к тому, что уже написано в `CLAUDE.md`**: пересчёт запускается не только при монтировании
элемента. Он также срабатывает при resize окна, при некоторых изменениях `Storage`, и — что важнее всего —
**при каждом вызове `Controller.toggle(name)`, если у целевого контроллера нет своего `update`-хендлера**
(`core/controller.js`: `if(active.update) active.update(); else Layer.update()`). Нативный
`components/torrents.js` вызывает `Layer.update(scroll.render(true))` явно сразу после перестройки списка
результатов — тот же паттерн, что наш `refreshGrid()`, только независимо переизобретённый. Это подтверждает:
явный вызов `Layer.update()` после смены контента — идиоматичный путь, а не костыль в обход API.

Формула размера шрифта (`Layer.size()`): `Math.max(window.innerWidth / 84.17 * fs, 10.6)`px (`fs` — 0.9/1/1.05
по настройке размера интерфейса). Отсюда и берётся живо замеренная в `CLAUDE.md` константа `1em ≈ 15.2073px`
(для окна ~1280px) — не совпадение, а прямое следствие этой формулы.

### Filter (`interaction/filter.js`)

Все находки `CLAUDE.md` подтверждены почти построчно:

- `.filter--search` открывает `selectSearch()` — ровно тот список пунктов, что уже описан: пустой
  «Указать название» (открывает `SearchInput`), «Глобальный поиск», история из
  `Storage.get('user_clarifys')[movie.id]`, альт-названия фильма, комбинации title+year из
  `search_one`/`search_two`.
- `SearchInput` (`interaction/search_input.js`) — действительно полноэкранный виджет с виртуальной
  клавиатурой (`Keybord`), а не текстовый промпт.
- Вложенные `.items`-подменю: клик по пункту с `.items` открывает **дочерний** `Select.show`, чей
  `onSelect` вызывает `filter.onSelect(type, a, b)` и затем **сам** переоткрывает родительский список —
  ровно то поведение, из-за которого «вложенные» пики самовосстанавливаются, а плоские — нет (см. ниже
  про `Select`).
- `filter.set(type, items)` кладёт в `data[type]` и вызывает `toggle()`, который показывает/прячет чипы
  по признаку «есть элементы» — повторный вызов `set()` это единственный способ обновить панель, отдельного
  метода `refresh` нет.
- `addButtonBack()` — нативный аналог нашей строки «К списку серий»: чип `.filter--back`, откатывающий
  либо через `Activity.back()`, либо повторным `push` экрана `full`.

### Select (`interaction/select.js`) — самое сильное подтверждение

Два независимых пути закрытия подтверждены дословно:

- `close()` — единственный путь, вызывающий `onBack`.
- Успешный пик (внутри обработчика клика в `bind()`) вызывает `hide()` в одиночку — никогда не трогает
  `Controller`, никогда не вызывает `onBack`.

Ровно тот баг, что был вычислен из минифицированной сборки в
[`system-design/lampa-navigation-contract.md`](../system-design/lampa-navigation-contract.md), подтверждён
первоисточником байт в байт. Дополнение: контроллер `'select'` регистрирует и `left`, и `back` на один и
тот же (корректный, с `onBack`) путь закрытия — ломается только *пик*, не выход стрелкой влево.

### Controller (`core/controller.js`)

`run(name)` — `if(active[name]) active[name](params)`: отсутствующий хендлер направления — мёртвая
клавиша, дефолтного поведения нет. Подтверждено дословно.

`collectionSet(html, append)` — конкатенирует `.selector`-совпадения из обоих аргументов в один плоский
массив для `Navigator`. Нативные вызовы (`components/torrents.js`, `plugins/online/component.js`) делают
это в порядке **(тело списка, шапка/карточка)** — тот же порядок, что уже используется у нас.

## Storage, Noty, SettingsApi

- **`Lampa.Storage`** (`core/storage/storage.js`): `field(name)` — значение настройки (с дефолтом из
  `Params`), отдельно от `get`/`set` (произвольные сырые значения). `cache(name, max, empty)` — готовый
  read/prune-on-write хелпер с ограничением размера, если когда-нибудь понадобится LRU-кэш вместо
  самодельного.
- **`Lampa.Noty`** (`interaction/noty.js`, 36 строк): `show(text, {style, time})`. Без очереди — второй
  вызов во время показа первого просто заменяет текст и сбрасывает таймер.
- **`Lampa.SettingsApi`** (`interaction/settings/api.js`): `addComponent(data)` регистрирует раздел
  настроек и создаёт для него пустой шаблон. `addParam(data)` — не просто описание поля: для
  `type: 'select'/'input'` он же вызывает `Params.select(...)`, для `'trigger'` — `Params.trigger(...)`.
  То есть **регистрация параметра через `addParam` — единственный способ, которым дефолтное значение
  реально попадает в `Storage.field()`**, отдельного шага нет.

## TMDB: важное уточнение к `CLAUDE.md`

Раньше не было способа проверить это иначе, чем по факту работы кода — теперь подтверждено: в Lampa
**два разных TMDB-модуля**, и только один — настоящий `Lampa.TMDB`.

- **`core/tmdb/tmdb.js`** — это и есть глобальный `Lampa.TMDB`. Вся его поверхность: `api(url)`, `key()`,
  `image(url)`, `broken()`. Тонкий построитель URL с учётом пользовательского прокси плюс встроенный
  публичный API-ключ. **У него нет `img()`, `full()`, `search()` и т.п.**
- **`core/api/sources/tmdb.js`** (1292 строки) — куда более богатый модуль (`main, category, full, list,
  search, person, seasons, find, get, img, parsePG, parseCountries, genres, keywords, videos`), но он
  **не выставлен глобально как `Lampa.TMDB`** — он зарегистрирован как источник `'tmdb'` внутри
  `Lampa.Api`, и его методы доступны только через `Lampa.Api.*` (например, `Lampa.Api.img(path, size)`
  для URL постера — не `Lampa.TMDB.img()`, которого не существует).

Наш `Plugins/TorrentModPlugin/tmdb.js` вызывает только `Lampa.TMDB.key()` и `Lampa.TMDB.api()` — это
ровно та пара методов, что реально существует. Использование корректно, править ничего не нужно; это
уточнение — на будущее, если когда-нибудь понадобится URL постера или что-то ещё из богатого набора.

## Дизайн-токены и CSS

Глобальных токенов немного — `sass/app.scss`: `$speed: 0.2s`, `$offset: 1.5em`, точки останова
`$media_lg/md/sm/xm/xs` (991/767/580/480/400px). **Отдельного файла цветовых переменных нет** — цвета
почти везде заданы литералами `rgba(255,255,255, α)`/`rgba(0,0,0, α)` поверх тёмной темы; переключение
тёмной/светлой/«стеклянной» темы — на уровне JS (классы на `<body>`, `core/layer.js`), не через SCSS-токены.

Размеры почти всюду в `em`, и корневой `font-size` считается в JS (`Layer.size()`) по формуле
`Math.max(window.innerWidth / 84.17 * fs, 10.6)`px — см. выше, это прямой источник константы `≈15.2px`.

Конвенция именования — BEM-подобная (не строгая): `&__part`, `&--modifier` через SCSS-вложенность, но
некоторые под-элементы называются через дефис без второго `--` (`.explorer__files-head`, не
`.explorer__files--head`) — как и в нашем коде. Единственный по-настоящему универсальный «токен» в системе
— класс `.focus`, переключаемый `Controller` и используемый в SCSS повсеместно как индикатор фокуса.
`$offset` (1.5em) — стандартный горизонтальный отступ прокручиваемых списков; наш живо замеренный «~1.4em»
у Online Mod — в пределах погрешности от этого источника (другая настройка размера интерфейса или чуть
другая вёрстка у стороннего плагина).

## Сезоны/серии/раздачи: нативные парсеры

Два файла, на которые стоило посмотреть в первую очередь:

### `components/torrents/parser.js` — разбор заголовка раздачи

Публичная функция `general(title)` возвращает `{season, seasons, episodes, year, quality, hdr,
resolution}`. По сравнению с нашим `Plugins/TorrentModPlugin/release-parsing.js` — покрывает больше
форматов, встречающихся на реальных русскоязычных/украинских трекерах:

- **Диапазоны сезонов**: `[S01-02]`, «4-6 сезон», «сезон 4-6» — у нас такого нет, сезон парсится только
  как одно число.
- **Диапазоны серий с указанием общего числа**: «12 из 12», «1-4 серия из 10», «04x01-07 из 10» — у нас
  `episodeFrom`/`episodeTo` парсятся, но без учёта суффикса «из N» и связанной с ним неоднозначности
  (единственное число вида «12 из 12» там трактуется как диапазон `1-12`, а не как серия №12).
- **Украинский текст**: «серія», «з» (украинское «из») — у нас в `release-parsing.js` этого нет вообще,
  только русские и английские маркеры.
- **Отсечение диапазона годов от диапазона серий**: если оба «конца» диапазона ≥1900 — это не серии
  (`(1990-2024)`), эвристика оформлена явно.
- **Защита от совпадения качества-подстроки внахлёст**: у списка меток качества регэксп для каждой метки
  экранирует дефис и добавляет negative lookahead, чтобы, например, `WEB-DL` не подхватывался как часть
  более длинной `WEB-DLRip`. У нас в `release-parsing.js` порядок веток в `matchOne` тоже подобран так,
  чтобы более специфичные варианты проверялись раньше, но явного lookahead-щита нет — полагаемся только
  на порядок проверки, что менее надёжно при добавлении новых меток в произвольном месте списка.
- **HDR определяется отдельно от разрешения** (`HDR`/`Dolby Vision` как отдельное поле, не примешано в
  общий «quality» бакет) — у нас так же, `hdr` отдельное поле, тут совпадает.

Тестовые случаи (`spec/seasons_parser.spec.js`) — хороший источник реальных сырых заголовков для
регрессионных проверок, если решим расширять `release-parsing.js`: диапазоны сезонов вида «1-8 сезон
(1-73 из 73)», украиноязычные «Серія 4 з 8», множественные написания «сезон: 4» с двоеточием и без.

### `utils/episodes_parser.js` — сопоставление файла с номером серии

Другая задача: не разбор ЗАГОЛОВКА раздачи, а сопоставление КОНКРЕТНОГО ФАЙЛА внутри торрента (или сезон-
пака) с номером сезона/серии — по имени файла и папки. Алгоритм проще: список регэкспов по убыванию
специфичности (`S01E05`, `1x05`, `S0105`, «season 1 episode 5», «серия 5», «[05]», « - 05» и т.д.),
прогоняется по имени файла, затем (если сезон не найден) — по имени папки отдельным, более узким списком
регэкспов. Если серия так и не нашлась — пробуется «имя файла начинается с числа». Результат используется
как ключ дедупликации (`hash_string`) для истории просмотра.

У нас в плагине эта задача не стоит в том же виде (мы сопоставляем РАЗДАЧУ с целевым эпизодом по данным
Jackett, не разбираем список файлов внутри уже скачиваемого торрента) — `pickBestFile()` в
`Plugins/TorrentModPlugin/smart-preload.js` делает нечто похожее (`preloadFileScore`), но по более узкому
набору сигналов. Если когда-нибудь понадобится точнее выбирать файл внутри season-pack с нестандартными
именами файлов — это готовый список проверенных на реальных раздачах регэкспов для сверки.

### `components/torrents/voices.js` — список студий озвучки

Курируемый список ~700 названий переводчиков/студий (используется нативным экраном раздач для
автозаполнения фильтра «Перевод» через простой поиск подстроки). Наш `TRANSLATOR_STUDIOS` в
`release-parsing.js` — на порядок короче и специально курируемый под то, что реально встречалось в логах
`torrent_mod_debug`. Не повод переписывать на полный список (наш подход — «расширять по мере находок в
логах», не «взять всё, что есть», см. `CLAUDE.md`) — но хороший источник имён, если конкретная студия не
распознаётся.

## Примеры плагинов, на что смотреть и на что нет

- **`components/torrents.js`** (нативный экран поиска раздач, не в `plugins/`, но самый релевантный
  референс) — подтверждает практически каждую деталь нашей обвязки Explorer/Filter/Controller/Scroll один
  в один, вплоть до порядка аргументов `collectionSet` и места вызова `Layer.update()`.
- **`plugins/online/online.js`+`component.js`** — **не подходит как референс Explorer/Filter** несмотря
  на похожее название. Построен на `Lampa.Files` (`interaction/files_old.js` — буквально «старые файлы» в
  дереве исходников), это до-Explorer поколение API. Полезен для другого: паттерн
  `contextmenu`/`hover:long` для меню действий, и пересчёт `scroll.minus()` по `resize`-листенеру
  (альтернатива нашему подходу через триггеры `Layer.update()`, оба варианта рабочие).
- **`plugins/twolines/twolines.js`** — тривиальный пример плагина, который просто добавляет `<style>` в
  `<body>`; директива `@@include(...)` в нём — макрос gulp-сборки самой Lampa, работает только в их
  pipeline, к нашей esbuild-сборке не относится.

## Сборка самой Lampa (для контекста, не для копирования)

`gulpfile.js` — Rollup (бандлинг `src/app.js` в один IIFE, Babel) плюс отдельный Rollup-проход на каждый
плагин (`plugins/<name>/<name>.js` → свой IIFE + сжатый inline CSS из Sass). Целевые сборки — `webos`/
`tizen`/`github`. Не имеет прямого отношения к нашей esbuild-сборке `TorrentModPlugin.bundle.js`, но
подтверждает: подход «каждый плагин — свой отдельный IIFE» — это то, как сама Lampa собирает свои
плагины, не самодеятельность нашего пайплайна.
