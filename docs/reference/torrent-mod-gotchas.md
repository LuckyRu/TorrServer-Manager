# Torrent Mod: справочник по граблям JS/API

Короткий список чисто технических ловушек — регэкспы, контракты API, порядок проверок — найденных при
разработке Torrent Mod. Каждый пункт самодостаточен: конкретный факт + общий урок, без истории «как
дошли до жизни такой». За полной историей конкретного бага — в `system-design/`, где она есть (ссылки
внутри пунктов).

## `\b` не работает вокруг кириллицы

Регэксп voiceType для «Дубляж» в `matchOne()` (`search/release-parsing.js`) был
`/\bдубляж\b|\bdub\b/i` — альтернатива на кириллице никогда не матчилась, потому что JS `\b` определён
через `\w` (`[A-Za-z0-9_]`, кириллицы там нет), и ни с одной стороны кириллического слова граница не
формируется. Проверено: `/\bдубляж\b/i.test('x264 Дубляж')` → `false`, `/дубляж/i.test(...)` → `true`.

**Урок**: никогда не оборачивай `\b` вокруг кириллической (или любой не-ASCII-word-character)
альтернативы в JS-регэкспе — она молча перестаёт матчиться, а не кидает ошибку, поэтому ничего не
просигнализирует об этом кроме явной построчной сверки с реальными данными.

## `Lampa.Component.create` глотает исключения конструктора

Контракт подтверждён чтением исходника: `Lampa.Component.create(object)` делает `new ctor(object)` в
try/catch и **при любом исключении молча подменяет компонент на встроенный `nocomponent`** («Здесь
пусто») — без видимой ошибки на экране, только `console.log('Component', 'create error', ...)` в
devtools. Реальная опечатка/несуществующий вызов API внутри конструктора выглядит как пустой экран, а
не как краш.

Отдельно: **`Lampa.Utils.escape` не существует** в этой сборке Lampa — именно вызов несуществующего
метода однажды и был причиной такой тихой подмены. Для экранирования HTML нужен свой локальный
`escapeHtml()`, а не предположение, что Lampa предоставляет готовый.

Подробнее про полный контракт жизненного цикла компонента — в
[`lampa-plugin-api.md`](lampa-plugin-api.md#componentactivity-два-разных-слоя).

## Identity для персиста ≠ identity для дедупа в одном ответе

`candidateIdentity()` (`domain/results-core.js`) предпочитал `item.link` вместо `title+size`, когда у
кандидата не было magnet-ссылки. У части индексеров (без magnet, например NoNaMe Club) этот `link`
проксируется через сервер Jackett с закодированным в query токеном пути — токен **разный у двух
отдельных запросов на один и тот же релиз** (подтверждено сравнением двух живых fetch подряд). Из-за
этого персист выбора торрента для такого индексера был нерабочим сразу после перезагрузки страницы: пул
перезапрашивался с нуля, ссылка приходила другая, сохранённый id не совпадал ни с чем. Исправлено
порядком `magnet || title+'|'+size` — `link` из идентичности убран совсем.

**Урок**: identity-ключ для стабильности **во времени** (персист выбора пользователя, который должен
резолвиться и после перезагрузки) — более строгое требование, чем identity только для дедупа **внутри
одного ответа**. URL, который сервер перевыпускает заново на каждый запрос, не годится для первого даже
если вполне пригоден для второго.

## Убрал guard на вызывающей стороне — проверь порядок проверок внутри callee

Селектор пикера вызывал `pool.filter(...)` раньше, чем проверял, загружался ли пул хоть раз —
воспроизводимо, потому что раньше вызывающий код сам защищался от этого случая явным guard'ом, а когда
guard убрали (по теории «селектор и так покажет `'loading'`»), никто не проверил, что порядок проверок
**внутри самого селектора** защищает именно тот доступ, который защищал удалённый guard. Ловилось как
`TypeError: Cannot read properties of null (reading 'filter')` — достижимо потому, что быстро
резолвящийся источник данных (список эпизодов из TMDB) делал экран интерактивным задолго до того, как
резолвился более медленный источник (агрегированный поиск по трекерам, до ~40с).

**Урок**: убирая guard на стороне вызывающего кода с рассуждением «теперь это делает callee» —
явно проверь порядок проверок **внутри** callee и убедись, что он защищает именно тот доступ, который
защищал удалённый guard. Не полагайся на категориальное сходство («там же есть проверка на loading») —
проверяй буквальный порядок операторов.
