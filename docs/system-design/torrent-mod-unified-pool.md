# План: единый пул раздач Torrent Mod

Процессный документ: план большой перестройки Torrent Mod (не ADR — решение о направлении уже
принято, здесь зафиксированы этапы, мотивация и проверенные факты, на которые опирается план).
Открытые вопросы, на которые ещё нет ответа, помечены явно.

## Мотивация

Torrent Mod запускается **из уже найденного в TMDB произведения**: у нас есть id, названия,
сезоны, длительность серий. Значит, вся работа плагина — это подбор торрентов **под уже
известный контекст**, а не самостоятельный поиск фильмов. Из этого следует два решения:

1. **Фильм и сериал — разные сценарии.** У сериала есть сезон → эпизод → «следующая серия»;
   у фильма — один «эпизод». Смешивать их в одной логике — ошибка, которую делает сама Lampa
   (нативный торрент-экран не различает). Разделяем явно.
2. **Один пул раздач + локальная фильтрация.** Вместо «пул сезона + точечный поиск эпизода»
   загружаем один набор раздач (для сериала — всего сериала, не сезона) и фильтруем его локально
   из state через селекторы. Именно для этого был выделен domain-слой: стор, интеракторы,
   селекторы, состояние без гонок (generation-счётчики).

## Проверенные факты (живые замеры, 2026-08-07)

- Пагинации у агрегированного Jackett-эндпоинта **нет**: `Limit=100` не расширяет ответ,
  `Offset=50` игнорируется. Доступно ровно то, что сайт/парсер отдал по запросу (у NoNaMe — 50
  результатов на запрос, `CacheMaxResultsPerIndexer=1000` в конфиге не влияет). Компенсация —
  **мерж нескольких запросов** (название + название+год): поиск уже умеет объединять и
  дедуплицировать, разные запросы возвращают разные подмножества.
- Fallback-поиск эпизода (`SxxExx` отдельным запросом, когда пул пуст) **бесполезен**: если по
  названию ничего не нашлось, точечный запрос по тому же названию тоже ничего не найдёт.
  Убираем. Единственный сетевой поиск после старта — ручной запрос пользователя (customQuery).
- Главный параметр для пользователя — **битрейт потока** (расчётный `estimateBitrateMbps`),
  а не размер файла. Битрейт становится отдельным измерением фильтра и отображается в карточке
  раздачи.

## Этапы

### Этап 0 — Тесты парсинга (фундамент)

Отдельный харнесс на Node (без зависимостей, `node:assert`), скрипт `npm run test:plugin`.
Бандлится esbuild (исходники плагина — ES-модули в `.js` без `type: module`; esbuild собирает
тест в CJS для Node). Покрытие:

- `parseSignals`/`parseRelease` на зоопарке реальных заголовков из настроенных индексаторов
  Jackett (см. `test/fixtures/`): фильмы (новинки / топ десятилетия / старьё), сериалы, аниме.
  Только русский язык.
- Форматы: `S01E01`, `01x01`, `4x01-07 из 10`, `12 из 12`, `S1-5E1-72 of 98`, «1-8 сезон
  (1-73 из 73)», «2 сезон», «сезон 4-6», украинские «Серія 4 з 8», `WEB-DL`/`WEB-DLRip`
  (lookahead-защита от вложенных меток), `Remux`/`BDRip`/`HDTV`/`CAM`, `HDR`/`DV`, `5.1/7.1/2.0`,
  `x265/HEVC`, `dual audio`, переводчики с точками (`Кубик.в.Кубе`), кириллица без `\b`.
- `scoreCandidate` (гейт), `applyStateFilters`, построение фильтров из пула — с моками браузерных
  глобалов (`Lampa`, `document`) по мере необходимости.
- Закрываемая дыра: **диапазоны сезонов `S1-5`** — критично для модели «весь сериал в пуле»
  (такой пак должен матчиться с любым сезоном 1–5).

### Этап 1 — Единый пул раздач

- `seasonPool` (привязан к сезону) → общий `pool` без привязки к сезону.
- При старте `loadAllTorrents()`: 2 запроса (название, название+год) → мерж/дедуп → весь пул в
  state. Для сериала — раздачи всех сезонов.
- Смена сезона — **локально** (state.season), ноль сетевых запросов.
- Бейджи серий, опции фильтров — селекторы над единым пулом.

### Этап 2 — Явное разделение фильм / сериал

- Фильм: сразу список раздач + фильтры, автоплей при уверенном матче.
- Сериал: экран серий + бейджи + выбор сезона (локально) + фильтры + автоплей/пикер.
- Разные стартовые сценарии (`start()`), разный набор чипов фильтров.

### Этап 3 — Фильтры из реальных данных

- Качество (разрешение) — есть; Перевод — есть.
- Добавить: **Битрейт** (расчётный, диапазоны ~до 2 / 2–5 / 5–12 / 12+ Mbps). Показывается и в
  карточке кандидата (~Mbps).
- Опции фильтров строятся только из реально присутствующих в пуле значений (механизм `poolValues`
  уже есть — расширяется).

### Этап 4 — Клик по эпизоду

- Только локальная фильтрация из пула (гейт + скоринг).
- Fallback-поиск эпизода убран. `customQuery` — единственный сетевой поиск после старта.

### Этап 5 — Прогон live и релиз

- Живая проверка на реальном экземпляре (фильм, сериал, смена сезона, фильтры, автоплей).
- Релиз менеджера (bump `<Version>`, commit → publish → deploy → restart). Перед релизом — удалить
  dev-оверрайд `%LocalAppData%\TorrServer\dev-plugins\`, чтобы он не подменял embedded-бандл.

## Что не входит в план (сознательно)

- Мультиязычность: только русский.
- Пагинация Jackett: недоступна (см. проверенные факты).
- Глобальный поиск Lampa (`Search.addSource`) и next-episode через плейлист плеера — отдельные
  темы, зафиксированы в обсуждении, но не в этом плане.

## Статус

- **Этап 0 — выполнен** (коммиты `6bc8e58`, `cec4130` и тестовый слой в рабочем дереве): зоопарк
  фикстур из живого Jackett, `npm run test:plugin` (62 теста: парсинг + domain-юниты + smoke-потоки
  домена под мок-браузером), фиксы `parseSignals`/`parseRelease` (диапазоны сезонов `S1-5`,
  ложное `2x2`, «сезон 1080p», `WEB-DLRip`, порядок HDR/DV, украинские маркеры), плюс `npm run
  test:e2e` — Playwright/headless Chromium против реального `/app/` с моком `torrent-search`
  (ловит `nocomponent`-класс багов: неимпортированные идентификаторы, падения конструктора
  компонента). E2E требует запущенный менеджер на `:8095` и `npx playwright install chromium`.
- **Этап 1 — выполнен** (в рабочем дереве, не закоммичен): единый whole-work `pool` вместо
  сезонного `seasonPool`, `loadAllTorrents` (один запрос по названию), смена сезона — локально
  без сети, клик по серии — локальная фильтрация пула, сетевой поиск только для `customQuery`.
  Плюс: поисковое имя по настройке Lampa `parse_lang` (вместо жёсткого «название Sxx»), синхронизация
  активного выбора в `Lampa.Filter` (`params.search`, `filter.set('sort')`).
  **Ленивая дозагрузка сезона** (закрывает лимитный случай, спроектирован architect): если у
  сезона локально ноль кандидатов (Jackett-лимит вытеснил сезон-специфичные раздачи из
  title-пула, пагинации нет) — один раз на сезон выполняется `Имя Sxx` + `Имя N сезон`, результат
  **мержится** в `pool` (не заменяет), сезон помечается `ready`/`error` в `state.seasonLoads` и
  больше не запрашивается до `requery`. Диапазонные паки `S1-5` этой дозагрузкой недостижимы —
  они живут в title-пуле (parseSignals матчит их с любым покрытым сезоном); их отсутствие в
  лимитной выдаче — осознанное ограничение.
- **Этап 3 — выполнен** (в рабочем дереве, не закоммичен): фильтры строятся из реальных данных
  пула. Добавлено измерение **Битрейт** (расчётный `estimateBitrateMbps`, бакеты до 2 / 2–5 /
  5–12 / 12+ Мбит/с) — опции только из реально присутствующих в пуле бакетов; битрейт показывается
  и в карточке кандидата (`~X Mbps`). Персистентность как у перевода/качества (global + per-movie).
- **Прямой путь воспроизведения (без нативного экрана торрентов)** — выполнен (см. план
  «прямой путь» в обсуждении): `Lampa.Torrent.start()` больше НЕ вызывается. Вместо него:
  `Lampa.Torserver.hash({link})` → поллинг `Torserver.files(hash)` → `pickBestFile()` по
  `file_stats` → **`initiatePreload()`** (первый GET к stream URL с `&preload` — именно этот запрос
  заставляет TorrServer качать файл в кэш; без него `/cache`-поллинг вечно показывал 0%, найдено
  архитектором: поллинг читает состояние, но не запускает загрузку) → `/cache`-поллинг до
  duration-based target → `Torserver.stream(path, hash, id)` → `Lampa.Player.play({url, timeline,
  playlist})`. Три native-сайд-эффекта компенсируются явно: `Favorite.add('history')`, `timeline:
  Timeline.view(Torserver.parse(...).hash)`, `data.playlist` из playable-файлов пака (next-episode).
  Таймаут не закрывает preload раньше выбора файла (metadata `.torrent`-ссылки может качаться
  дольше 60с — даётся двойной бюджет, потом честная ошибка).
  **Буфер считается ТОЛЬКО для выбранной серии** (`/cache` отдаёт per-piece битмап `Pieces` +
  `PiecesLength`; по байтовому диапазону выбранного файла `[fileStart, fileEnd)` считаем
  непрерывный от начала буфер — левые файлы торрента больше не раздувают готовность, найдено
  живой проверкой API TorrServer). `targetBytes = min(битрейт × 25с, размер файла)`, битрейт
  берётся из ffprobe (`format.bit_rate`, fallback `size/duration`, fallback оценка по заголовку).
  **Предзагрузка следующей серии** (`torrent_mod_preload_next`, вкл.): пока серия играет, плагин
  слушает `PlayerVideo.listener('timeupdate')` и, когда текущий файл доходит до ~85% (или осталось
  ≤60с), просит TorrServer предзагрузить следующий playable-файл пака — переход по плейлисту
  начинается без паузы на дозагрузку. Ничего не показывает, в плеер/playlist не лезет (ADR-0003),
  один следующий файл, fire-and-forget.
