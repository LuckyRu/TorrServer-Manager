# MVP: предпочтительная встроенная аудиодорожка в сериалах

Статус: реализовано в `playback/audio-tracks.js` и `playback/smart-preload.js`; нужна live-проверка
на WebOS с реальной многодорожечной раздачей. Документ описывает минимально полезную поддержку
нескольких аудиодорожек одного медиафайла без форка TorrServer. Для причин, по которым это именно
MVP, см. [предыдущее исследование](torrent-mod-audio-tracks-backlog.md).

## Решение в одной фразе

Перед запуском **каждой** серии Torrent Mod всегда читает метаданные через
`/gst/{hash}/probe?index={fileId}`. Список дорожек сразу передаётся плееру. Если для сериала и
сезона известно предпочтение пользователя по конкретной студии, resolver выбирает её; если нет —
выбирается первая audio-дорожка. Серия запускается через GST/HLS с полученным `audio={trackIndex}`.

Ручной выбор другой дорожки создаёт кандидат нового предпочтения, сохраняет позицию и
**перезапускает этот же файл** через GST/HLS URL с `audio={trackIndex}&seconds={position}`. Кандидат
сохраняется для сезона только после успешного запуска. Для следующей серии тот же preflight
вызывается лениво в момент playlist-перехода.

Это не бесшовное HLS-переключение: TorrServer создаёт только один аудиопоток на GST-задачу.
Пользователь увидит короткое состояние «Переключение перевода…»; HLS manifest может ждать до 60
секунд. Задержка складывается из получения нужных кусочков файла из torrent и инициализации GST
pipeline; их фактический вклад измеряется live-spike, а не выводится из исходника. MVP сознательно
отказывается от direct transport: единственный путь — `probe → GST/HLS`. Первый запуск ждёт metadata
probe, нужные torrent-части и инициализацию pipeline. В обмен не меняются
бинарник TorrServer, его обновление и глобальные механизмы Lampa.

## Цели и границы

### Цели

- Дать пользователю список реальных встроенных озвучек одного файла, включая язык, название,
  кодек и каналы, если TorrServer их сообщил.
- Автоматически применить ранее выбранную студию к каждой серии сезонного пака, даже когда её
  порядковый номер аудиодорожки меняется между файлами.
- Всегда передавать плееру список реальных дорожек выбранного файла, включая случай без сохранённого
  предпочтения.
- При отсутствии preference запускать первую audio-дорожку детерминированно, а не полагаться на
  default нативного video engine.
- При переключении продолжать просмотр примерно с той же позиции и не оставлять параллельные GST
  задачи для одного hash.
- Сохранить переключение следующей серии в сезонном паке и текущий lifecycle `PlaybackSession`.

### Не цели MVP

- Не добавлять `TYPE=AUDIO` в HLS manifest и не делать выбор мгновенным.
- Не проксировать, не переписывать и не запрашивать параллельно несколько `master.m3u8`.
- Не менять TorrServer, его процесс обновления или `Services/PluginHub.cs`.
- Не сохранять порядковый номер дорожки как пользовательское предпочтение: он может различаться
  между сериями.
- Не использовать `Lampa.Torserver.stream()` и не задавать `url_reserve`: native direct player не
  является частью контракта аудиодорожек и субтитров Torrent Mod. Тихий прогрев использует только
  явный `/stream?...&preload`, чтобы не создать GST-задачу до выбора дорожки.

## Почему путь безопасен относительно старой попытки

Субтитры TorrServer отдаёт отдельными WebVTT-плейлистами в одном master manifest. Аудио выбирается
при создании pipeline параметром `audio=N` и попадает в единственный A/V fMP4 output. Следовательно,
параллельные аудио rendition URL в переписанном manifest-е будут соревноваться и ломать текущий
поток.

> **Актуализация.** Раньше здесь было сказано, что задача хранится по ключу `hash` и запрос с другим
> аудио заменяет предыдущую. Это перестало быть правдой с переходом на сессионный ключ: `audio`
> входит в `sessionToken(client, hash, fileID, audio)`, поэтому смена дорожки создаёт **вторую**
> задачу, а не заменяет первую. Старая живёт до подчистки по неактивности и всё это время занимает
> слот из `MaxTasks` (по умолчанию 6). См.
> [`three-identities-client-pipeline-torrent.md`](three-identities-client-pipeline-torrent.md).

MVP делает ровно один переход: сначала останавливает/заменяет текущий player, затем открывает один
новый GST URL. `/gst/.../probe` получает только метаданные и не должен запрашивать `master.m3u8`.
Это устраняет последовательную цепочку тяжёлых manifest-запросов, из-за которой версия v1.17.23
зависала.

## Поток данных

```text
серия или файл сезонного пака
  → GET /gst/{hash}/probe?index={fileId}
  → нормализация аудиодорожек → voiceovers в Player data
  → preference есть? resolver находит дорожку N : первая audio-дорожка
  → Player.play(GST audio=N)
  → пользователь выбирает дорожку N
  → запомнить currentTime; отключить старые listeners
  → Player.play(тот же файл, GST audio=N, seconds=currentTime)
  → TorrServer отдаёт уже полученные/нужные torrent-части; Lampa продолжает с сохранённой позиции
```

Запрос пробника начинается сразу после того, как `Torserver.files` подтвердил выбранный `fileId`, и
всегда является gate перед `Player.play`. Он привязывается к конкретному `sessionId + fileId`; если
пользователь успел перейти к другой серии, закрыть плеер или запустить новую раздачу, поздний ответ
игнорируется.

## Контракты

### TorrServer

Запрос:

```text
GET http://{torrserver}/gst/{hash}/probe?index={fileId}
```

Нужны только аудио-записи из ответа probe: стабильный индекс, `language`, `title`/label, codec и
число или layout каналов. Плагин не должен делать дополнительный запрос к `/ffp`: в этом MVP
источник правды — GST probe, поскольку именно его индекс передаётся в `audio=N`.

TorrServer выполняет probe отдельной программой `gst-discoverer` и кэширует результат по
`hash + fileId` на один час. Последующий `master.m3u8` вызывает тот же `Service.Probe`, поэтому
получит кэш и не запустит discoverer повторно. Probe читает источник и тем самым может начать
загрузку нужных torrent-частей. При этом он **не** оставляет живую GST-задачу: pipeline создаёт
только `master.m3u8` через `GetOrAdd → EnsureInit`. Смена аудио пересоздаёт этот pipeline, но не
вызывает `torr.DropTorrent(hash)` — код не делает намеренный сброс torrent cache. Реальное наличие
нужных кусков и длительность переключения подтверждаются live-spike; 60-секундный manifest timeout
остаётся обязательным.

Запуск выбранной дорожки:

```text
GET http://{torrserver}/gst/{hash}/master.m3u8?index={fileId}&audio={trackIndex}&seconds={position}
```

`position` передаётся только если он является конечным неотрицательным числом. Полный URL строится
одной функцией, все параметры кодируются. `hls_manifest_timeout` остаётся `60000`.

Первая audio-дорожка определяется по первому элементу probe с `Type == 'audio'`; в GST URL
передаётся её настоящий `Index`. `audio=0` не является рабочим fallback-параметром MVP: хотя
TorrServer при его отсутствии берёт первую audio-запись, основной путь всегда строит URL с индексом
из probe.

### Lampa

Lampa принимает `data.voiceovers`: панель дорожек выводит эти объекты и вызывает их `onSelect`.
MVP передаёт `voiceovers` из probe всегда, включая единственную audio-дорожку: это единый источник
истины для активного плеера, а не условный UI-декор.
Объект MVP имеет форму:

```js
{
  index: 2,
  language: 'ru',
  label: 'Dubbed by Studio',
  extra: { codec: 'AAC', channels: 2 },
  selected: false,
  onSelect: function (track) { switchToGstTrack(track.index); }
}
```

Поле `data.ffprobe` для этого не подходит: Lampa использует его, чтобы подписать уже найденные
нативные/HLS-треки, но не создаёт из него переключаемые источники. Плейлист и переход между сериями
должны получать такой же audio-state через общий builder data, а не через глобальный patch
`Lampa.Player.play`.

У playlist item `url` разрешён не только как строка, но и как функция `(continuePlayback) => void`.
В этом случае Lampa сама показывает loading и ждёт callback; перед ним функция заменяет `item.url`
на готовый string GST URL и задаёт таймаут. Это публично используемый
Lampa contract для отложенного получения URL и основной механизм preflight следующей серии.

### Предпочтение перевода

Текущий `voiceType` (`Дубляж`, `Многоголосый` и т. п.) остаётся фильтром **раздач**. Он недостаточен
для выбора встроенного трека: два разных дубляжа в одном MKV имеют один тип, но разные студии.
Поэтому MVP хранит отдельное, более точное предпочтение:

```js
// torrent_mod_audio_preference, ключ: movie.id + ':' + season
{
  language: 'ru',
  titleNormalized: 'студиякубиквкубе',
  label: 'Кубик в Кубе'
}
```

Оно создаётся или заменяется только при явном выборе пользователя в меню дорожек **после успешного
GST `canplay` для выбранной дорожки**. В нём не хранится `trackIndex`: индексы различаются от серии
к серии. До `canplay` выбор живёт в `pendingAudioPreference`, поэтому нерабочая дорожка не отравит
автоматический выбор следующих серий. `resolvePreferredTrack(preference, tracks)`
сопоставляет нормализованные язык и title/label; при нуле или нескольких равносильных совпадениях
возвращает `null`. Никакого эвристического выбора «первый дубляж» нет: он чаще даст неверную студию.

## Preflight сериалов и playlist

Для первой выбранной серии preflight всегда выполняется до `Player.play`. При этом пользователь не
остаётся на экране результатов: Torrent Mod синхронно монтирует публичный `Lampa.Player.render()`
как нативную оболочку Player с loading-состоянием, но без media source. Поскольку штатные панели
Lampa до `Player.play` внутренне скрыты, поверх этой же оболочки сразу монтируется минимальный
spinner со стадиями подключения к раздаче, получения файлов, анализа дорожек и запуска. После
успешного probe оболочка без `detach()` передаётся обычному `Player.play`; overlay удаляется только
по `Player.ready`, поэтому между preflight и нативным плеером нет чёрного промежутка. `data.url`
получает GST URL с
`audio=N`, где N — однозначно найденная preference-дорожка или первая audio-дорожка ответа probe.
`url_reserve` не добавляется: основной источник уже GST, другого транспорта нет.

Верхнеуровневый `data.url` нельзя сделать функцией: Lampa передаёт его напрямую в `replace()`,
`indexOf()` и `PlayerVideo.url()`. Lazy URL поддержан только у playlist item. Поэтому ранняя
оболочка использует `Player.render()`, но не вызывает `Player.play` с фиктивным URL и не создаёт
преждевременный GST task. Исходный controller запоминается до её монтирования; Back во время любой
стадии отменяет player scope, закрывает оболочку и делает поздние XHR безвредными.

Если preference не нашлась однозначно, выбирается первая audio-дорожка и показывается краткое
объяснение; preference не удаляется, потому что она может встретиться в следующем файле. Если probe
не удался или не содержит audio, media source не запускается, оболочка закрывается и Torrent Mod
показывает причину. Сетевой/5xx сбой probe повторяется один раз внутри открытой оболочки;
детерминированная ошибка формата не повторяется. Нельзя тихо запустить direct stream с неизвестными
дорожками.

Для остальных файлов сезонного пака `buildPlaylist()` создаёт lazy URL-функции, а не заранее
пробит все файлы. При штатном `Playlist.next()` Lampa вызывает функцию, та всегда делает probe,
заполняет элемент списком `voiceovers` и готовым GST URL для preference либо первой дорожки, а потом
вызывает callback Lampa. Это сохраняет правильный перевод и при ручном раннем переходе «Следующая»;
нет гонки с готовым `playlist` и нет N процессов `gst-discoverer` сразу.

После разрешения URL следующий playlist item кэшируется как строка на время текущей сессии. При
возврате назад его не надо probe-ить заново. Сервис TorrServer независимо хранит metadata cache
один час.

## Проектируемые компоненты

| Компонент | Ответственность |
|---|---|
| `audio-tracks.js` | Чистая нормализация Go/camelCase JSON probe, label и консервативный resolver preference. |
| `smart-preload.js` | Владеет player scope, его file scopes, ранней оболочкой Player и storage preference по `movie.id + season`; всегда запускает probe до media source и очищает ресурсы через lifecycle. |
| Player-data builder | Всегда применяет preflight, создаёт lazy URLs для следующих файлов и передаёт `voiceovers` из probe в каждый Player data. |
| `switchToGstTrack` | Единственная точка контролируемого рестарта: защита от двойного клика, чтение позиции, UI ожидания, restart и rollback/error-message. |
| Tests | Pure tests нормализации/выбора первой дорожки/preference/URL/позднего ответа и smoke-test формы `Player.play` с `voiceovers` для фильма, серии и playlist item. |

Новый код остаётся внутри `Plugins/TorrentModPlugin/playback/`; `PluginHub` и C# не участвуют.

## Состояние и инварианты

Для каждого активного `PlaybackSession` хранится:

```text
probes: Map<fileId, Track[]>
transports: Map<fileId, {url, voiceovers, audioIndex}>
activeFile
activeAudioIndex: null | number // null только до успешного GST start или в состоянии ошибки
audioPreference: null | AudioTrackPreference
pendingAudioPreference: null | AudioTrackPreference
switchState: idle | switching
sessionId: increasing number
playerScope: Lifecycle
fileScope: Lifecycle // child playerScope для текущего fileId
phase: registering | metadata | probing | starting | started
preparationMounted: boolean
```

- У одного session в момент времени максимум один действующий запрос probe и один переход audio.
- Ответ probe применим только пока живы соответствующие player scope и file scope; смена `fileId`
  уничтожает scope старого запроса.
- `activeAudioIndex === null` допустим только до успешного GST start или после ошибки; активный
  playback всегда имеет индекс, полученный из probe.
- Клик по уже выбранному треку не перезапускает поток.
- Без `audioPreference` выбранная по умолчанию дорожка — первая audio-дорожка из ответа probe; она
  не превращается в preference, пока пользователь явно не выберет другую через меню.
- `pendingAudioPreference` записывается в storage только на `canplay` нового GST source. Ошибка,
  закрытие player или supersede session отбрасывают его.
- При destroy/новом playback все handlers и pending-результаты становятся неактуальными.
- Player scope владеет register/files, ранней оболочкой и общим Player lifecycle. File scope владеет
  probe/retry, track-switch listeners и прогревом следующей серии; смена `fileId` уничтожает только
  прежний file scope.
- Оболочка Player монтируется сразу после создания player scope и не содержит URL; `Player.play`
  вызывается только после успешного preflight.
- Back в preparation-состоянии закрывает оболочку и уничтожает player scope до того, как
  отменённый callback сможет вызвать отложенный `action:add`, probe или Player.
- Автопереход на следующую серию всегда повторно резолвит fingerprint по metadata нового `fileId`;
  нельзя переносить индексы аудио из другого файла пака.

## Алгоритм переключения

1. Проверить `switchState`, валидность `trackIndex`, наличие GST base URL и что выбран другой трек.
2. Получить текущую позицию из `Lampa.PlayerVideo`; если её нет, использовать `0`.
3. Установить `switching`, чтобы destroy предыдущего Player не завершил сессию, а повторные клики
   были проигнорированы.
4. Показать неблокирующее уведомление «Переключение перевода…».
5. Собрать новые player data для **того же** `fileId`: `url` — GST URL выбранного трека. `url_reserve`
   не задаётся: второй одновременно работающий GST источник недопустим, а повторный fallback не имеет
   другого транспорта.
6. Перезапустить Player через подтверждённый в spike lifecycle-вызов, передав сохранённую позицию в
   GST `seconds`. Восстановить те же title, card, timeline и playlist.
7. На `canplay` снять `switchState` и атомарно записать `pendingAudioPreference` для
   `movie.id + season`.
8. На timeout/fatal error отбросить pending preference и показать состояние ошибки с действием
   «Повторить GST» для той же дорожки и «Вернуться к выбору файла». Не делать автоматический retry
   loop и не переключаться на direct transport.

Реализация использует `Lampa.Player.close()` и затем новый `Lampa.Player.play(data)`: это не
бесшовная смена, поэтому приемка на целевом устройстве по-прежнему обязательна.

## Ошибки и UX

| Ситуация | Поведение |
|---|---|
| GST отсутствует, `/probe` вернул сетевую/5xx ошибку или timeout | Оставить оболочку открытой и повторить probe один раз; после второго отказа закрыть её и показать причину. Preference не менять. |
| `/probe` вернул 4xx или unsupported container | Не повторять детерминированную ошибку; закрыть оболочку и сообщить о неподдерживаемом формате. |
| Back во время register/files/probe | Немедленно уничтожить player scope и закрыть оболочку; поздний ответ не запускает media и не делает отложенный `action:add`. |
| Есть preference, но probe не нашёл однозначную дорожку | Не угадывать: начать GST с первой audio-дорожкой, показать краткое объяснение и оставить список дорожек. |
| Запуск выбранной вручную GST-дорожки завершился ошибкой | Отбросить pending preference и сообщить, что перевод не переключён; не делать автоматический retry loop. |
| В probe одна audio-дорожка | Всё равно передать её в `voiceovers`; выбор остаётся первой и preference не создаётся автоматически. |
| Нет названия/языка | Показать «Дорожка 1», «Дорожка 2»; не скрывать рабочую дорожку. |
| Пользователь выбрал дорожку во время закрытия/перехода серии | Игнорировать клик и поздние ответы уничтоженного file scope. |
| GST не прогрелся за 60 с или вернул fatal error | Сообщить, что перевод не переключён; без цикла повторов. |
| Пользователь быстро выбирает два перевода | Первый переход единственный, последующие клики блокируются до результата. |

## Live-приёмка

На одной известной раздаче с минимум тремя аудиодорожками нужно записать в DevTools:

1. Фактический JSON `/gst/{hash}/probe?index={fileId}` и соответствие его индексов `audio=N`.
2. Время первого и повторного probe, а также первого `master.m3u8` после него. Подтвердить, что
   probe не запускает/не заменяет GST-задачу, но master использует его metadata cache.
3. Точный Lampa lifecycle для замены source: отсутствие двух одновременно живых video/pipeline,
   сохранение позиции и корректный Back.
4. Первый GST старт и смену `audio=0 → 1 → 2`, включая таймаут и выбор следующей серии в паке.
5. Переключить студию вручную, закрыть player, открыть следующую серию: preference должен совпасть
   по названию, а не по старому индексу. Проверить также отсутствие совпадения и неоднозначное
   совпадение; проверить, что preference не записывается при GST timeout/error.
6. Поведение на целевом WebOS-устройстве и в desktop браузере: labels, пульт, возврат из player,
   единственная дорожка в `voiceovers` и GST-first запуск без сохранённого preference.

Критерий завершения: все три реальные дорожки воспроизводятся по их GST URL, position
восстанавливается с погрешностью не более 5 секунд, а закрытие/следующая серия не оставляют listener
или GST request от прошлого файла.

## Последующий путь

Если MVP востребован, полноценная версия переносит переключение в TorrServer: один GST task выдаёт
video rendition и отдельные audio renditions, master manifest объявляет `EXT-X-MEDIA:TYPE=AUDIO`.
Тогда Lampa переключит `hls.audioTrack` без перезапуска. MVP намеренно изолирован так, чтобы этот
переход заменил только источник track list и `onSelect`, а не поиск, сессию и UI-контракт.
