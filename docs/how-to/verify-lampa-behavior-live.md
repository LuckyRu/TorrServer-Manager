# Как проверить реальное поведение Lampa вживую (а не угадать)

У Lampa нет публичной документации API. Единственный надёжный источник — сам минифицированный код
(`app.min.js`) и живой инстанс приложения. Этот процесс использовался многократно при разработке Torrent
Mod и каждый раз находил что-то, что угадывание пропустило бы — см.
[`system-design/lampa-navigation-contract.md`](../system-design/lampa-navigation-contract.md) за
конкретными примерами найденных так багов.

## Предпосылка

Работающий инстанс менеджера + Plugin Hub на `:8095`, зарегистрированный dev-сервер в `.claude/launch.json`
(`{"name":"plugin-hub","url":"http://127.0.0.1:8095","port":8095}`) для доступа через браузерные MCP-тулы
без запуска отдельного процесса — `preview_start` просто присоединяется к уже работающему серверу.

## Шаги

1. Открыть `http://127.0.0.1:8095/app/` в браузере (не LAN-адрес — браузерные MCP-тулы требуют
   подтверждения на каждое действие для не-loopback адресов; `127.0.0.1` работает без этого).

2. Затянуть исходник ядра Lampa в память вкладки:
   ```js
   fetch('http://127.0.0.1:8095/app/app.min.js').then(r => r.text()).then(t => {
     window.__lampaSrc = t;
   });
   ```
   Для стороннего плагина — тот же приём с его локально закэшированным URL (виден в
   `Object.keys(window.Lampa)` не поможет; смотреть `document.scripts` на `/plugins/<hash>.js`, или через
   `GET /api/config` в JSON-ответе PluginHub — там `localPath` у каждого плагина).

3. Точечный поиск, не массовое чтение:
   ```js
   var i = window.__lampaSrc.indexOf('function Filter(');
   window.__lampaSrc.slice(i, i + 900);
   ```
   200–900 символов контекста обычно достаточно, чтобы понять сигнатуру/логику одной функции/класса. Не
   тянуть больше, чем нужно для конкретного вопроса — см. дисциплину по авторскому праву ниже.

4. Скриптовать реальные действия напрямую через публичный `Lampa.*` API, не через синтетические клики:
   ```js
   Lampa.Activity.push({ url:'', title:'Test', component:'torrent_mod', movie:{...}, season:1 });
   Lampa.Controller.move('right');
   Lampa.Controller.enter();
   Lampa.Controller.back();
   Lampa.Controller.enabled().name;              // текущий активный именованный контроллер
   document.querySelector('.focus');              // что реально в фокусе
   Lampa.Activity.all();                           // весь стек активностей
   ```

5. **При подозрении на баг в своей интеграции — обязательно повторить на голом коде Lampa**, без единой
   строчки своего плагина (пример: `Lampa.Select.show({...})` на нативном главном экране). Различает
   «сломал я» от «так себя ведёт сама Lampa» — оба реальных случая в
   [`lampa-navigation-contract.md`](../system-design/lampa-navigation-contract.md) нашлись именно так, и
   один раз результат был неожиданным (баг оказался общим, не специфичным для плагина).

6. Проверять контрпримером, если результат похож на баг, но не укладывается в объяснение. Пример из
   практики: похожее на «зависшую навигацию» поведение при повторном тестировании оказалось не багом
   вообще — просто в тестовом сценарии было на одно нажатие Back больше, чем нужно для конкретной
   последовательности открытых меню. Пересчитать шаги раньше, чем объявлять баг.

## Дисциплина по объёму цитирования

Тянуть только маленькие целевые фрагменты (сигнатуры функций, ~100–900 символов контекста), описывать
находки своими словами, никогда не воспроизводить большие куски исходника дословно ни в коде, ни в
документации, ни в переписке. Если случайно вытянули слишком много — сократить/переформулировать, а не
оставить как есть.

## Проверка HTTP-эндпоинтов напрямую

Для серверной части (не Lampa, а собственный `PluginHub.cs`) — `curl` быстрее браузера:
```bash
curl -s http://127.0.0.1:8095/api/config
curl -s -X POST http://127.0.0.1:8095/api/plugins/refresh -d ""
curl -s -D - -o /dev/null "http://127.0.0.1:8095/plugins/<hash>.js" | grep -i cache-control
```
