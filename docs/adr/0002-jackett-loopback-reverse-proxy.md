# ADR-0002: Jackett остаётся на loopback, LAN-доступ через прокси

**Статус:** Принято
**Дата:** 2026-08-05

## Контекст

Lampa 3.2.8+ имеет собственную нативную настройку «Тип парсера: Jackett» (прямой URL + API-ключ,
отдельно от `SmartTsPlugin`'а RuTracker-only прокси) — ей нужен Jackett, достижимый по LAN, а не только
с `127.0.0.1`, где Jackett слушает сейчас (сознательно — TorrServer и Jackett оба управляются как обычные
дочерние процессы без служб Windows и без UAC на каждый клик, и Jackett дополнительно держат на
loopback как более консервативный выбор, поскольку у него есть собственная веб-панель с реальными
учётными данными индексаторов).

Проверили вживую: `AllowExternal`/`LocalBindAddress` в `ServerConfig.json` Jackett есть, но
`JackettConsole.exe` при попытке слушать не-loopback адрес без прав администратора отвечает «Unable to
switch to public listening without admin rights» — это внутренняя проверка самого Jackett, не проблема
файрвола/URL-ACL (подтверждено: `netsh http add urlacl` для порта не помогает; ручной запуск
`JackettConsole.exe -z` с выводом в консоль показывает именно эту ошибку).

## Решение

Jackett остаётся loopback-only. `PluginHub` реверс-проксирует `GET`-запросы `/jackett/*` → `127.0.0.1:9117`
(путь + query string один в один), отдавая LAN-адрес прокси (`http://<lan-ip>:8095/jackett`) как
«Ссылку» для нативной настройки парсера Lampa, плюс API-ключ читается напрямую из `ServerConfig.json`
Jackett (`JackettController.GetApiKey()`).

## Рассмотренные варианты

- **Реверс-прокси через PluginHub (выбран)** — Jackett остаётся непривилегированным, вся LAN-поверхность
  контролируется нашим же кодом.
- **Запустить `JackettConsole.exe` с повышением (elevated)** — работает (elevated процесс проходит
  внутреннюю проверку), но возвращает UAC-запрос на каждый цикл старт/стоп/рестарт — то самое, ради ухода
  от чего Jackett и TorrServer вообще управляются как дочерние процессы, а не службы Windows. Отвергнут.
- **Запустить Jackett как службу Windows (LocalSystem)** — тоже прошёл бы внутреннюю проверку (служба
  LocalSystem may bind non-loopback), но реинтродуцирует сложность инсталляции/удаления службы, которую
  проект уже сознательно убрал раньше, плюс даёт Jackett заметно более широкие привилегии, чем у
  интерактивного пользователя. Отвергнут по обеим причинам.

## Последствия

- Jackett остаётся простым дочерним процессом без служб/UAC — согласовано с тем, как управляется
  TorrServer.
- Дополнительный сетевой хоп (LAN-устройство → PluginHub → loopback Jackett) для каждого обращения через
  нативный парсер Lampa — цена приемлема, трафик локальный.
- `/api/torrent-search` (агрегированный поиск для Torrent Mod) — отдельный эндпоинт, не переиспользует
  keyless `/jackett/*` прокси: ключ Jackett инжектится на сервере и не палится в JS клиента.
