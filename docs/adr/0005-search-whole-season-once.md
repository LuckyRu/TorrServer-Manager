# ADR-0005: Искать весь сезон один раз в фоне, а не по клику на серию

**Статус:** Принято
**Дата:** 2026-08-06

## Контекст

Изначально `selectEpisode(episode)` запускал новый поиск через `/api/torrent-search` на каждый клик по
серии — заново для каждой. Прямое наблюдение: «Я нажал смотреть, потом торрент мод. В этот момент у тебя
есть всё, чтобы начать искать уже все торренты и обогащать этими данными фильтры и описания серий.»

Действительно: как только известны название, сезон и хронометраж серии из TMDB (уже есть к моменту
рендера списка серий), любой поиск по конкретной серии строит те же query-варианты уровня сезона —
`buildQueries` без `episode` в target всегда даёт сезон-пак-подобные запросы, а не эпизод-специфичные.

## Решение

`ensureSeasonPool()` запускает поиск по сезону в фоне сразу при загрузке списка серий (`loadEpisodes`), не
дожидаясь клика. Результат используется трижды:

1. **Бейджи на строках серий** — `candidatesForEpisode(pool, number)` прогоняет тот же гейт+скоринг
   пайплайн против уже полученного пула, до того как пользователь что-либо выбрал.
2. **Опции Перевод/Качество** берутся из того, что реально есть в пуле (`poolValues()`), а не из
   статичного списка.
3. **Клик по серии переиспользует пул** вместо нового сетевого запроса, если пул уже покрывает эту
   серию — сезонный пак не имеет `explicitEpisode`, поэтому легитимно покрывает любую серию сезона, не
   только ту, под которой был впервые найден.

## Рассмотренные варианты

- **Поиск по сезону в фоне, переиспользование (выбран)**.
- **Поиск по клику на каждую серию (было раньше)** — отвергнут: N сетевых запросов к Jackett вместо
  одного на весь сезон, никакой информации до выбора, задержка на каждый клик.
- **Полная замена клика на переиспользование без сетевого фолбэка** — отвергнут: сезонный пак не
  гарантирует такой же recall, как точечный `SxxExx`-запрос (некоторые раздачи находятся только по точной
  метке серии). Клик делает свежий точечный поиск только если пул ничего не даёт для конкретной серии.
  Ручного изменения поискового запроса нет: контекст всегда берётся из TMDB.

## Последствия

- Один сетевой запрос на сезон вместо потенциально N — но это ДОПОЛНИТЕЛЬНЫЙ запрос к тому, что уже было
  (не замена), т.е. суммарная нагрузка на Jackett может не уменьшиться при активном клике по многим
  сериям — переиспользование скорее про латентность и UX, чем про снижение нагрузки.
- Побочно найден реальный баг парсинга: `\bдубляж\b` никогда не матчился (JS `\b` не распознаёт кириллицу
  как `\w`) — обнаружен через side-by-side тест пула против скоринга, а не абстрактным ревью кода. См.
  [`reference/torrent-mod-scoring-model.md`](../reference/torrent-mod-scoring-model.md).
