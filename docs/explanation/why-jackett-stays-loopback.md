# Почему Jackett не слушает LAN напрямую

Короткая версия решения — в [ADR-0002](../adr/0002-jackett-loopback-reverse-proxy.md). Этот документ —
про общий принцип, которому это решение следует, а не про сам факт.

## Общий принцип проекта: приватные сервисы остаются приватными, LAN-доступ — через нашу же прослойку

TorrServerManager управляет тремя HTTP-поверхностями: TorrServer (`:8090`), Plugin Hub (`:8095`) и Jackett
(`:9117`). Первые два сознательно открыты в LAN — телевизор должен до них достучаться напрямую, и ни один
не хранит ничего чувствительнее, чем адрес сервера и список включённых плагинов. Jackett — другое дело: у
него собственная веб-панель с реальными учётными данными индексаторов (логины/пароли трекеров), и его
API-ключ, попади он не в те руки в открытой домашней сети, даёт доступ к тем же данным.

Отсюда позиция: **Jackett остаётся на loopback не потому, что LAN небезопасен сам по себе, а потому что
не нужно расширять поверхность атаки сервиса с чувствительными учётными данными, когда для нужной
функциональности достаточно прокси через сервис, у которого чувствительных данных нет.**
`PluginHub`/`TorrServerManager` — тонкая, безопасная снаружи прослойка; сам Jackett — нет, и не должен
быть вынужден становиться такой прослойкой сам.

## Тот же принцип в других решениях этого проекта

- **Ffprobe-подтверждение реальных дорожек торрента** (Torrent Mod) сознательно не использует публичный
  фолбэк-сервис «Tracks Inspector», которым пользуется исходный плагин MediaInfo, когда `ffprobe`
  недоступен на этой сборке TorrServer — сторонний сервис вне инфраструктуры проекта, тот же принцип
  «локальное решение вместо внешней зависимости», даже когда внешняя чуть удобнее.
- **RuTracker в Jackett настраивается вручную**, через штатную веб-панель самого Jackett, а не программно
  через API менеджера (было раньше, убрано) — не про приватность, но про тот же дух: не пытаться
  автоматизировать то, что требует ручного взаимодействия с чужим сервисом (капча), вместо того чтобы
  городить хрупкий обход.

## Когда это стоит пересмотреть

Если Jackett когда-нибудь перестанет хранить учётные данные индексаторов сам (например, если появится
режим только с API-ключами трекеров без логина/пароля), аргумент «нельзя расширять поверхность атаки»
ослабнет — но решение всё равно стоит пересматривать явно новым ADR, а не тихой правкой кода.
